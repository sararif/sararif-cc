# sararif-cc — ตัดคลิป + ใส่ซับไทยลง CapCut ด้วยคำสั่งเดียว

> เครื่องมือที่ผมใช้จริงทุกวันกับ 3 ช่องของตัวเอง เอามาแบ่งให้ใช้
> ยังไม่ได้ขัดเกลาให้สวย แต่ใช้งานได้จริง — ถ้าติดตรงไหนบอกได้

**ทุกอย่างในนี้ฟรี ไม่ต้องมีคีย์ ไม่ต้องจ่ายอะไรเลย** ใช้ของที่ CapCut ถอดเสียงให้ฟรีอยู่แล้วเป็นวัตถุดิบ

---

## ทำอะไรได้บ้าง

| คำสั่ง | ทำอะไร |
|---|---|
| **`bun go.ts <โปรเจกต์>`** | **คำสั่งเดียวรันครบ** — ตัดช่วงเงียบ → ใส่ซับ → ใส่ hook |
| `bun cut.ts <โปรเจกต์>` | **ตัดช่วงเงียบออก** — ช่วงที่ไม่มีใครพูดถูกตัดทิ้ง คลิปวางต่อกันแบบไม่มีช่องว่าง ตัดครบทุกแทร็ก (ภาพ b-roll เสียง ซับ) พร้อมกัน |
| `bun order.ts <โปรเจกต์>` | **เรียงคลิปใหม่** — ตามเลขในชื่อไฟล์ หรือสั่งลำดับเองด้วย `--order` |
| `bun cc.ts <โปรเจกต์>` | **ใส่ซับไทยที่แบ่งบรรทัดเป็น** — ไม่ตัดกลางคำ ไม่ทิ้งคำเชื่อมค้างท้าย |
| `bun cc.ts <โปรเจกต์> --highlight "ฟรี,ลดน้ำหนัก"` | ซับ + **เน้นคำสำคัญเป็นสีเหลือง** |
| `bun hook.ts <โปรเจกต์> --l1 ".." --l2 ".."` | **ใส่ hook ตัวใหญ่ช่วงต้นคลิป** ใส่ `[วงเล็บ]` ครอบคำไหน คำนั้นเหลือง |

## โหลดมาแล้วทำอะไรก่อน

```bash
git clone https://github.com/sararif/sararif-cc.git
cd sararif-cc
bun doctor.ts     # เช็คว่าเครื่องมีของครบไหม
bun setup.ts      # ตั้งค่าเป็นของคุณเอง + บอกว่าปรับอะไรได้บ้าง
```

**`bun setup.ts` สำคัญ** — มันจะบอกว่าค่าทุกอย่างในเครื่องมือนี้ **ปรับได้ ไม่ใช่ของตายตัว**
ค่าเริ่มต้นคือฟอร์แมตที่ผมใช้กับช่องตัวเอง (คลิป 25-30 วิ · ซับ 16 ตัว/บรรทัด · เน้นคำสีเหลือง)
ซึ่ง**ไม่จำเป็นต้องเหมาะกับคุณ** — คลิปคุณอาจเป็นสายสอนที่ต้องยาว 90 วิ ก็ตั้งเอาได้

## เริ่มยังไง — คำสั่งเดียวจบ

```bash
# ── ใน CapCut ── ใส่คลิปลงไทม์ไลน์ → Text → Auto captions → ภาษาไทย → ปิด CapCut
bun go.ts myproj --highlight "คำที่อยากเน้น" --l1 "ตัดคลิป 1 ชั่วโมง" --l2 "เหลือ [3 นาที]"
# ── กลับไปเปิด CapCut ── ดูผล แก้ซับที่ยังไม่ถูกใจ ใส่เพลง แล้ว export
```

`go.ts` รันให้ครบ 3 ขั้นในทีเดียว: **ตัดช่วงเงียบ → ใส่ซับ → ใส่ hook**
ปิด CapCut รอบเดียว ไม่ต้องสลับไปมา

| ตัวเลือกของ `go.ts` | |
|---|---|
| `--highlight "ก,ข"` | คำที่จะเน้นสีเหลืองในซับ |
| `--l1 --l2 --l3` | ข้อความ hook (ไม่ใส่ = ข้ามขั้น hook) |
| `--no-cut` | ไม่ต้องตัดช่วงเงียบ เอาแค่ซับ |
| `--dry` | ดูก่อนว่าจะตัดอะไรออก แล้วหยุด |
| `--track N` | เลือกแทร็กซับที่ใช้เป็นตัวจับคำพูด |

**เรียงคลิปใหม่ ต้องทำก่อนกด Auto captions**

```bash
bun order.ts myproj      # แล้วค่อยเข้า CapCut กด Auto captions → bun go.ts myproj
```

**อยากคุมทีละขั้น** ก็รันแยกได้ — `cut.ts` · `cc.ts` · `hook.ts` (ธงครบกว่า `go.ts`)

> ⚠️ **`order.ts` ต้องมาก่อน Auto captions เสมอ** — การเรียงคลิปใหม่ทำให้ซับเดิมไม่ตรงกับภาพ
> มันเลยลบซับทิ้งให้ ถ้าเรียงทีหลังจะเสียซับที่ CapCut ถอดไว้ ต้องกดถอดใหม่

ทุกคำสั่งใส่ `--dry` เพื่อดูก่อนได้ ไม่แตะโปรเจกต์
ทุกคำสั่งสำรองไฟล์เดิมไว้เสมอ (`draft_info.json.PRE_*_BAK`)

**ยังไม่ครบทั้ง flow** — ดูหัวข้อ [ทำอะไรไม่ได้](#-ทำอะไรไม่ได้-ยัง) ก่อนคาดหวัง

## ปัญหาที่ตัวนี้แก้

CapCut ทำซับไทยอัตโนมัติได้ **แต่แบ่งบรรทัดไม่เป็น**

ผมทดสอบบนมือถือจริงเมื่อ 31 ส.ค. 69 กับคลิปพูด 45 วินาที:

| | ผลที่ได้ |
|---|---|
| **CapCut auto-caption** | ซับ **3 ก้อน** ก้อนละ 11–20 วินาที · ข้อความ 5–7 บรรทัดค้างบนจอทีเดียว **อ่านไม่ทัน** |
| **ตัวนี้** | ซับ **39 บรรทัด** บรรทัดละ ~1 วินาที · ไม่ตัดกลางคำ · ไม่ทิ้งคำเชื่อมค้างท้าย |

สาเหตุที่ CapCut ทำไม่ได้: **ภาษาไทยไม่มีเว้นวรรค** มันเลยหาจุดแบ่งวลีไม่เจอ (ภาษาอังกฤษมันแบ่งให้ปกติ)
ตัวนี้ใช้ **pythainlp** ตัดคำไทยจริง แล้วแบ่งบรรทัดตามกฎที่ผมกลั่นมาจากงานจริง

---

## กฎการแบ่งบรรทัดที่ใส่ไว้

1. **ไม่ตัดกลางคำ** — ตัดคำด้วย pythainlp newmm
2. **ไม่ทิ้งคำลงท้ายไว้โดด** — `ครับ ค่ะ คะ จ้า นะครับ อะ อ่ะ เนี่ย ปุ๊บ` เกาะท้ายบรรทัดเดิมเสมอ
3. **ขึ้นบรรทัดใหม่ที่คำเชื่อม** — `ก็ ซึ่ง แต่ เพราะ ดังนั้น พอ ถ้า`
4. **ไม่ปล่อยคำเชื่อม/บุพบท/กริยาค้างท้ายบรรทัด** — `ใน จาก กับ ที่ ว่า ไม่ ต้อง จะ ได้ เพื่อที่จะ ของการ` รวม **75 คำ**
5. **ไม่ขึ้นต้นบรรทัดด้วยคำที่ต้องเกาะคำหน้า** — `นะ ครับ เนาะ หรอก นี้ นั้น เลย ๆ` รวม **26 คำ**
6. **ไม่ขึ้นต้นบรรทัดด้วยคำอังกฤษ** — `คนใน / Hall อ่ะ` อ่านสะดุด ต้องเป็น `คนใน Hall อ่ะ`
7. **คุมความยาว** ไม่ยาวเกิน ไม่สั้นเกิน

> รายการคำพวกนี้ไม่ได้นั่งคิดเอง — มาจากการเอาซับที่โปรแกรมตัด ไปเทียบกับซับที่คนตัดเองทีละบรรทัด
> แล้วเก็บทุกคำที่โดนแก้ ยิ่งตัดเองเยอะ ลิสต์ยิ่งแม่น

**ตัวอย่างที่ต่างกันจริง:**

```
ก่อน:  ...มีความสามารถใน    ←  "ใน" ค้างท้าย อ่านสะดุด
       การหาเงิน...
หลัง:  ...มีความสามารถในการ
       หาเงิน...

ก่อน:  จุดที่เราต้อง        ←  ประโยคปิดถูกหั่นเป็น 2 ท่อน
       วางแผน
หลัง:  จุดที่เราต้องวางแผน
```

| **ทางได้ข้อความ** | ✅ ต้องมี 1 ใน 3 | ทาง A ไม่ต้องติดตั้งอะไร — ดูหัวข้อถัดไป |


### ทาง B · ElevenLabs Scribe — เวลาแม่นระดับคำ

สมัครที่ https://elevenlabs.io เอา API key มาใส่ไฟล์เดียว จบ

```bash
echo 'ELEVENLABS_API_KEY=คีย์ของคุณ' > ~/.sararif-cc.env
```

ราคาราว **฿1 ต่อคลิป 3 นาที** · ใช้ได้กับ Mac ทุกรุ่น · **เวลาแม่นระดับคำ** เอาไปเลือกจุดตัดต่อได้จริง
(ใช้คีย์ของคุณเอง ผมไม่ได้แถมคีย์ และไม่ได้เก็บค่าอะไรจากตรงนี้)

### ทาง C · whisper.cpp ในเครื่อง — ฟรี แต่มีข้อแลก 2 ข้อ

```bash
brew install whisper-cpp

mkdir -p ~/.sararif-cc/models
curl -L -o ~/.sararif-cc/models/ggml-large-v3-turbo.bin \
  https://huggingface.co/ggerganov/whisper.cpp/resolve/main/ggml-large-v3-turbo.bin
```

> ⚠️ **ข้อแลกที่ 1 — เวลาเพี้ยน** วัดจริงกับคลิปพูด 45 วินาที: วินาทีที่ 42 ถูกรายงานเป็น **53**
> ยิ่งคลิปยาวยิ่งเพี้ยน **เอาไปเลือกจุดตัดต่อหรือทำ cc ไม่ได้** เหมาะกับ "อยากรู้ว่าพูดอะไร" เท่านั้น
>
> ⚠️ **ข้อแลกที่ 2 — ติดตั้งนานถ้า Mac ไม่ใหม่พอ** brew มีตัวสำเร็จรูปให้เฉพาะ **macOS Sonoma (14) ขึ้นไป**
> ถ้าเครื่องเป็น **Ventura (13) หรือ Monterey (12)** มันจะ compile เอง **อาจกินเวลา 20–40 นาที**
> เช็คเวอร์ชันเครื่องด้วย `sw_vers -productVersion` · บวกโหลดโมเดลอีก ~1.5GB
>
> **ถ้าเครื่องไม่ใช่ Sonoma ขึ้นไป ข้ามทาง C ไปเลย** — ใช้ทาง A ที่ฟรีและไม่ต้องติดตั้งอะไรดีกว่า

โมเดลเล็กกว่าใช้ `ggml-base.bin` (~150MB) เร็วกว่าแต่แม่นน้อยกว่า
เก็บ whisper/โมเดลไว้ที่อื่นสั่งทับได้ด้วย `WHISPER_CLI=...` และ `WHISPER_MODEL=...`

## เริ่มใช้

**1. ตรวจเครื่องก่อน — อันนี้ทำเป็นอย่างแรกเสมอ**

```bash
bun doctor.ts
```

มันจะบอกว่าขาดอะไร **พร้อมคำสั่งที่ต้องพิมพ์** ก๊อปไปวางได้เลย ขึ้น `✅ พร้อมใช้งาน` ถึงไปต่อ

**2. เปิด CapCut สร้างโปรเจกต์ ใส่คลิปลงไทม์ไลน์ แล้วปิด CapCut**

จำชื่อโปรเจกต์ไว้ (ชื่อที่ตั้งใน CapCut นั่นแหละ)

**3. ดูก่อนว่าจะแบ่งบรรทัดยังไง (ยังไม่เขียนลงโปรเจกต์)**

ทางฟรี (ค่าเริ่มต้น) — กด Auto captions ใน CapCut ก่อน แล้วปิด CapCut จากนั้น:
```bash
bun cc.ts ชื่อโปรเจกต์ --dry
```
ไม่ต้องใส่ธงอะไรเพิ่ม **ไม่ใส่ไฟล์คลิป = ใช้ทางฟรีเสมอ**

ทางที่มีคีย์ Scribe / whisper — ใส่ไฟล์คลิปมาด้วยถึงจะถอดเสียงใหม่:
```bash
bun cc.ts ชื่อโปรเจกต์ ~/Downloads/คลิปของคุณ.MOV --dry
```

**4. พอใจแล้วค่อยเขียนจริง — เอา `--dry` ออก**

```bash
bun cc.ts ชื่อโปรเจกต์
```

**5. เปิด CapCut ดูผล** — ถ้าซับไม่ขึ้น ให้ปิด CapCut สนิทก่อนแล้วเปิดใหม่ (มันแคชไฟล์ไว้)

## ตัวเลือกที่มี

```bash
bun cc.ts <โปรเจกต์> [คลิป...] [ตัวเลือก]

--dry                  แบ่งวลีให้ดูอย่างเดียว ไม่เขียนลง CapCut
--engine capcut        อ่านซับที่ CapCut ถอดไว้แล้ว (ฟรี · ค่าเริ่มต้นเมื่อไม่ใส่ไฟล์คลิป)
--engine scribe|local  ถอดเสียงใหม่จากไฟล์คลิป (ต้องมีคีย์ / whisper)
--track N              เลือกแทร็กข้อความ (ดูเลขที่ใช้ได้จากที่มันพิมพ์ให้ตอนรัน)
--keep-source          ไม่ต้องลบซับเดิมของ CapCut (ค่าปกติคือลบให้)
--highlight "ก,ข"      เน้นคำเหล่านี้เป็นสีเหลืองในซับ
--hl-color "#FFD400"   เปลี่ยนสีคำที่เน้น
--maxchars 16          ความยาวสูงสุดต่อบรรทัด
--y -0.80              ตำแหน่งแนวตั้ง (-1 = ล่างสุด)
--size 15              ขนาดตัวอักษร
```

```bash
bun cut.ts <โปรเจกต์> [ตัวเลือก]

--dry                  ดูว่าจะตัดอะไรออกบ้าง ไม่แตะโปรเจกต์
--head 0.20            เผื่อเวลาก่อนเริ่มพูด (วินาที)
--tail 0.40            เผื่อเวลาหลังพูดจบ
--gap 0.60             ช่องเงียบสั้นกว่านี้ไม่ตัด (กันคลิปกระตุกเป็นห้วนๆ)
--min 0.30             ท่อนที่สั้นกว่านี้ทิ้งไป
--track N              เลือกแทร็กซับที่ใช้เป็นตัวจับว่าใครพูดตอนไหน
```

```bash
bun order.ts <โปรเจกต์> [ตัวเลือก]

--dry                  ดูลำดับเดิม/ลำดับใหม่ ไม่แตะโปรเจกต์
--desc                 เรียงย้อนกลับ
--order "A,B,C"        สั่งลำดับเอง (คลิปที่ไม่ได้พิมพ์ ต่อท้ายตามลำดับเดิม ไม่หาย)
```

```bash
bun hook.ts <โปรเจกต์> --l1 ".." [ตัวเลือก]

--l1 --l2 --l3         ข้อความบรรทัดที่ 1-3   ([คำ] = คำนั้นสีเหลือง)
--start 0  --dur 3     เริ่มโชว์วินาทีที่เท่าไหร่ นานแค่ไหน
--y 0.55  --size 22    ตำแหน่งแนวตั้ง / ขนาดตัวอักษร
--color "#FFD400"      สีของคำใน [วงเล็บ]
```

```bash
bun cc.ts myproj a.MOV b.MOV
bun cc.ts myproj a.MOV:0 b.MOV:12.5      # หรือกำหนดวินาทีที่เริ่มเอง
```

## ❌ ทำอะไรไม่ได้ (ยัง)

ตัวนี้ทำ **ช่วงกลางที่น่าเบื่อที่สุด** ให้ ไม่ได้ทำแทนทั้งกระบวนการ ที่ยังต้องทำเองคือ:

| ขั้นตอน | สถานะ |
|---|---|
| นำคลิปเข้า CapCut · วางลงไทม์ไลน์ | ❌ ทำเองใน CapCut |
| กด Auto captions ให้ CapCut ถอดเสียง | ❌ ทำเองใน CapCut (ตัวนี้อ่านผลที่มันถอดไว้ ไม่ได้สั่งให้ถอด) |
| เรียงคลิป · ตัดช่วงเงียบ · ซับ · คำเน้นสี · hook | ✅ **สคริปต์ทำให้** |
| ตรวจซับแล้วแก้คำที่ยังไม่ถูกใจ | ❌ ทำเองใน CapCut — ตัดตรงกับที่คนตัดเองราว **58%** |
| ใส่เพลง · เสียงประกอบ · ภาพแทรก (b-roll) · ทรานซิชัน | ❌ ทำเองใน CapCut |
| Export · โพสต์ลงแพลตฟอร์ม | ❌ ทำเองทั้งหมด |

**ข้อจำกัดที่ต้องรู้:**

- **ต้องปิด CapCut ก่อนรันคำสั่ง** แล้วเปิดใหม่เพื่อดูผล (`go.ts` ทำให้เหลือสลับรอบเดียว)

- **`cut.ts` ต้องมีซับก่อน** เพราะใช้ซับเป็นตัวจับว่าใครพูดตอนไหน คลิปที่ไม่มีคนพูดใช้ไม่ได้

- **ซับที่ได้ยังต้องมาไล่แก้เอง** กฎ "ประโยคใหม่ = ใบใหม่" กับ "คำนาม+ส่วนขยายห้ามแยกใบ" ยังบังคับด้วยโค้ดไม่ได้ ต้องใช้ตาคน

- **แทร็กสติกเกอร์/เอฟเฟกต์ไม่ถูกตัดตาม** `cut.ts` — มันเตือนให้ แต่ต้องไปขยับเอง

- **Mac เท่านั้น** และต้องใช้ CapCut เวอร์ชันคอม (เวอร์ชันมือถือใช้ไม่ได้)

## ปรับให้เป็นฟอร์แมตของคุณเอง

ค่าเริ่มต้นทั้งหมดคือฟอร์แมตที่ผมใช้ **แก้ได้หมด** สั่ง `bun setup.ts` แล้วแก้ไฟล์
`~/.sararif-cc/format.json` — ในไฟล์มีหมายเหตุบอกไว้ทุกบรรทัดว่าค่านั้นทำอะไร

| ค่า | เริ่มต้น | หมายถึง |
|---|---|---|
| `clipSeconds` | 25-30 | ความยาวคลิปที่ตั้งเป้า |
| `silence.gap` | 0.6 | ช่องเงียบสั้นกว่านี้ไม่ตัด (ยิ่งน้อย ยิ่งกระชับ) |
| `silence.head` / `.tail` | 0.2 / 0.4 | เผื่อไว้ก่อนเริ่มพูด / หลังพูดจบ |
| `subtitle.maxchars` | 16 | ตัวอักษรสูงสุดต่อบรรทัดซับ |
| `subtitle.size` / `.y` | 15 / −0.8 | ขนาด / ตำแหน่งแนวตั้งของซับ |
| `hook.size` / `.y` / `.seconds` | 22 / 0.55 / 3 | ขนาด / ตำแหน่ง / โชว์กี่วินาที |
| `highlightColor` | `#FFD400` | สีคำที่เน้น |

**ตัวอย่างที่คนมักเปลี่ยน:**

```jsonc
"clipSeconds": { "min": 45, "max": 90 }        // คลิปสายสอน/รีวิว ยาวได้
"subtitle": { "maxchars": 11, "size": 30 }     // ซับใหญ่แบบคลิปไวรัล
"silence": { "gap": 0.35 }                     // ตัดกระชับกว่านี้
"highlightColor": "#00E676"                    // เปลี่ยนสีคำเน้นเป็นเขียว
```

**หรือพิมพ์ในคำสั่งเลยถ้าจะใช้ครั้งเดียว** — ธงในคำสั่งชนะไฟล์เสมอ

```bash
bun go.ts myproj --maxchars 11 --size 30
```

## สอนคำใหม่ให้มัน (ยิ่งใช้ยิ่งแม่น)

ตัวตัดคำไทย (pythainlp) ไม่รู้จักชื่อร้าน ชื่อคน ชื่อสินค้าของคุณ → มันจะซอยขาดกลาง
แล้วซับก็ขึ้นคนละบรรทัด เช่น `ทางสาย` / `บุรี` แทนที่จะเป็น `ทางสายบุรี`

**เจอคำไหนขาด เอาคำนั้นไปใส่ในไฟล์ แล้วรันใหม่ จบ** — ไม่ต้องแก้โค้ด

`~/.sararif-cc/words.txt` — คำที่ห้ามตัดกลาง 1 บรรทัด 1 คำ

```
# ชื่อร้าน ชื่อคน ชื่อสินค้า ชื่อสถานที่
ทางสายบุรี
ร้านลุงหนวด
โดโลไมท์
```

`~/.sararif-cc/fix.txt` — คำที่ถอดเสียงมาผิดบ่อย

```
# คำที่ได้ยินผิด = คำที่ถูก
บางกำ = บางกล่ำ
หะลาล = ฮาลาล
```

บรรทัดที่ขึ้นต้นด้วย `#` เป็นหมายเหตุ ระบบข้ามให้
เช็คว่าโหลดกี่คำแล้วด้วย `bun doctor.ts`

> คลังคำพวกนี้อยู่ในเครื่องคุณเอง ไม่ได้อยู่ในโค้ด — อัปเดตเครื่องมือทับก็ไม่หาย

## ⚠️ เรื่องที่ต้องรู้ก่อนใช้

**ปิด CapCut ก่อนเสมอ** — CapCut เก็บโปรเจกต์ทั้งก้อนไว้ในหน่วยความจำ แล้วเขียนทับตอนปิด
ถ้าเราแก้ไฟล์ตอนมันเปิดอยู่ **งานจะหายเงียบๆ ตอนคุณกด Cmd+Q**
ตัวนี้ปิด CapCut ให้เอง และถ้าเช็คไม่ได้ว่าปิดแล้วจริง **มันจะไม่ยอมเขียน** (ยอมไม่ทำ ดีกว่าทำแล้วงานหาย)

**มีไฟล์สำรองให้เสมอ** — ก่อนเขียนจะสำรองเป็น `draft_info.json.PRE_CC_BAK` ในโฟลเดอร์โปรเจกต์
ถ้าผลออกมาไม่ถูกใจ เอาไฟล์นั้นเขียนทับ `draft_info.json` กลับได้

**ทาง A ลบซับเดิมของ CapCut ให้เอง** — เพราะเราอ่านซับนั้นมาทำใหม่ ถ้าไม่ลบจะซ้อนกัน 2 ชั้นบนจอ
ของเดิมยังอยู่ในไฟล์สำรองครบ · อยากเก็บไว้เทียบใส่ `--keep-source`

**ทาง B/C "เพิ่ม" ซับ ไม่ได้ "แทนที่"** — ถ้าเคยมีซับอยู่แล้วจะได้ซับซ้อนกัน 2 ชั้น ลบของเก่าใน CapCut ก่อน

**🚨 ปิด CapCut ให้สนิทก่อนรันทุกครั้ง (Cmd+Q ไม่ใช่แค่ปิดหน้าต่าง)** — ถ้า CapCut เปิดค้างอยู่
ตอนมันถูกปิด **มันจะเขียนสถานะในหน่วยความจำทับไฟล์** งานที่เราเพิ่งเขียนหายหรือซ้อนกันได้
(เจอจริงตอนทดสอบ 1 ก.ย. 69 — ซับกลับมาซ้อนกันเพราะ CapCut เปิดค้างไว้ดูผล)

## 🪟 ใช้ Windows อยู่?

**ตอนนี้ยังไม่รองรับครับ ขอโทษด้วย** — เพราะโค้ดผูกกับ 2 อย่างที่เป็นของ Mac:

1. ที่อยู่โปรเจกต์ CapCut → `~/Movies/CapCut/User Data/Projects/com.lveditor.draft`
   บน Windows อยู่ที่ `%LOCALAPPDATA%\CapCut\User Data\Projects\com.lveditor.draft`
2. วิธีเช็คว่า CapCut เปิดอยู่ไหม → ใช้ `pgrep` / `ps` ซึ่ง Windows ใช้ `tasklist` แทน

**แต่ถ้าคุณใช้ Claude อยู่แล้ว แก้เองได้ไม่ยาก** — โยนไฟล์ `cc.ts` กับ `capcut_cc.py` ให้ Claude แล้วบอกว่า
*"ช่วยแก้ให้รองรับ Windows ด้วย: path โปรเจกต์เปลี่ยนเป็น %LOCALAPPDATA% และเปลี่ยนวิธีเช็คโปรเซสจาก pgrep เป็น tasklist"*

ถ้าใครแก้แล้วใช้ได้ **ส่งกลับมาให้ผมได้เลย จะได้แจกต่อให้คนอื่น**

- **แบ่งบรรทัดยังไม่เข้าใจความหมาย** — มันทำตามกฎการตัดคำ ไม่ได้เข้าใจว่าประโยคจบตรงไหน
  บางบรรทัดยังหั่นกลางความหมายอยู่ เช่น `หลายคนน่ะไม่ได้` / `วางแผนเลย...`
  **ถ้าอยากได้แบบเข้าใจความหมายจริง ต้องให้ AI ช่วยแบ่ง แล้วส่งเข้า `--phrases`**
- **ตัวนี้พึ่งโครงไฟล์ของ CapCut ที่ทางนั้นไม่ได้ประกาศ** — CapCut อัปเดตใหญ่เมื่อไหร่อาจพังได้ ผมรับประกันความต่อเนื่องให้ไม่ได้
- ยังไม่รองรับการแก้ซับที่ใส่ไปแล้ว (ต้องลบแล้วใส่ใหม่)

## ไฟล์ในชุดนี้

**ชุดนี้ครบในตัวเอง** โหลดไปแล้วใช้ได้เลย ไม่ต้องหาไฟล์เพิ่ม

```
sararif-cc/
├── README.md          ← ไฟล์นี้
├── doctor.ts          ← ตรวจเครื่องว่ามีของครบไหม (รันอันนี้ก่อนเสมอ)
├── cc.ts              ← ตัวหลัก คำสั่งเดียวจบ
├── segment.py         ← แบ่งวลีตามกฎไทย (มี --legacy ไว้เทียบแบบเดิม)
├── make_subs.py       ← ตัดคำไทยด้วย pythainlp + ตารางแก้คำที่ถอดเสียงผิดบ่อย
└── scripts/
    ├── from_capcut.py ← อ่านซับที่ CapCut ถอดไว้แล้ว (ทางฟรี ไม่ต้องถอดใหม่)
    ├── capcut_cc.py   ← เขียนซับลงไฟล์โปรเจกต์ CapCut
    ├── stt_clips.py   ← ถอดเสียงด้วย ElevenLabs Scribe (เสียเงิน แม่นระดับคำ)
    └── stt_local.py   ← ถอดเสียงด้วย whisper ในเครื่อง (ฟรี)
```

**อยากแก้คำที่ถอดเสียงผิดบ่อยของคุณเอง** (เช่นชื่อร้าน ชื่อแบรนด์) → แก้ตาราง `FIX` ใน `make_subs.py`
ในไฟล์มีตัวอย่างของผมอยู่ ลบทิ้งแล้วใส่ของคุณแทนได้เลย
